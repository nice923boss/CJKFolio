# Spike 17 Pre-mortem：標點擠壓（約物詰め／mojikumi aki）

日期：2026-07-18　對應 GAPS #45（Sprint 85 順延登記）

## 1. 最可能失敗的方式

擠壓規則憑「CJK 排版通則」印象立表，但本產品內建的**繁體字型是句逗置中設計**，
把置中標點壓成半形會裁到墨或使標點外觀走樣，做出來與參考書、與規範都不符。

## 2. 失敗機率

高（>50%）。Sprint 85 順延本項的理由正是「唯一 A 級來源真書無此形態」；
若不先量測字型墨跡、不取規範條文，等於憑印象寫排版規則（R1 違規）。

## 3. 早期訊號

- 量測顯示某類約物墨跡置中、兩側空白皆不足 0.5 em → 該類不可擠壓
- 規範條文對繁體另有排除條款 → 通則不可直接套繁中

## 4. 對策

1. 先量測內建字型每個約物在字身框內的墨跡邊界（A 級一手），得知哪一半是空白
2. 取 W3C CLREQ 條文原文（B 級，PLAN §10 已定案「標點擠壓以 CLREQ 為準」）
3. 兩者交叉驗算：每條規則的字對在本字型下擠壓後墨距是否仍 > 0
4. 只實作「量測與規範同時支持」的規則；規範排除繁體者不做，並記錄量測佐證

## 5. 放棄條件

- 取不到 CLREQ 條文原文（只剩二手轉述）→ 不立規則表，維持 GAPS #45 順延
- 規則 2〜6 有任一在本字型下擠壓後墨距 ≤ 0 → 該條不做
- float 字寬牽動的模組超過既有兩後端加 engine（表示模型不相容）→ 停工重議

## 6. 替代方案

擠壓量不寫死 0.5 em，改由樣式參數表達（同 Sprint 89 `wrap_margin_mm` 的
「幾何屬引擎、留白屬使用者」分工）。惟 CLREQ 條文明列半形為定值，v1 先照規範。

## 7. 預估誤差範圍

engine 純邏輯層改動小（1〜2 小時）；風險集中在「既有 754 測試是否因 int→float
字寬退步」與「預設關閉時輸出是否位元不變」，估半天。

# Spike 25 報告：ICC 色彩管理下的 RGB → CMYK 轉換

日期：2026-07-26　對應 GAPS #92 (a)(b)　結論：**條件性通過**

- **送印方向（a）可做**，但條件三條缺一不可：描述檔由使用者提供、灰階來源不進轉換、
  轉換後照過既有墨量檢查。預設仍是 Sprint 137 的轉灰＋警告，不是自動轉。
- **預覽反向（b）不做**：實測改用 ICC 反算會讓內文暖黑由 (20, 20, 20) 變 (52, 51, 51)
  且不再中性，是每一頁都看得到的退步，見 §2.7。

證據等級一律 A（本機自跑，數據見下；重現指令見 §4）。唯一非 A 的是「Japan Color 2001
Coated 設計總墨量 350%」這個業界說法，本機無該描述檔可驗，故**不作為任何判斷的依據**，
只列為未確認假設。

## 1. 成功標準與結果

| 標準 | 結果 |
| --- | --- |
| 轉換引擎是否需要新相依 | **否**。`PIL.ImageCms` 隨 Pillow 12.2.0 在庫，littleCMS 2.18 |
| §9 指定的 Japan Color 2001/2011 Coated 是否可用 | **本機沒有**。唯一的 CMYK 輸出描述檔是作業系統夾帶的 `RSWOP.icm`（Agfa : Swop Standard，218,103 bytes，美規塗布） |
| 轉換目標能否同時充當 X-1a／X-4 的 DestOutputProfile | **能**。`RSWOP.icm` 過既有 `validate_output_profile`，故「轉換目標＝宣告的輸出條件」可由同一個檔擔保 |
| 中性灰是否守 §9「灰階照片走單 K」 | **不守**。256 階中性灰有 254 階轉出 C／M／Y 非零 |
| 轉出影像 TAC 是否守 §9 的 320% | **守**（282.7%，relative colorimetric）。但這是 SWOP 自身墨量限制的結果，非本產品擔保 |
| rendering intent 可否由本產品代選 | **不可**。perceptual 對 relative colorimetric 單點分量差最大達 199／255，本機無任何依據可判孰優 |
| 300ppi 送印尺寸是否跑得動 | **是**。1748×2480 滿版 106 ms |
| 端到端是否寫得出合規 CMYK | **是**。`/DeviceCMYK`、無 `/Decode` 反相陣列，PyMuPDF 取原始樣本於 PIL 之外複量 TAC 282.7%，與 PIL 自報逐位吻合 |

## 2. 逐項量測

### 2.1 引擎與描述檔盤點

```
Pillow 12.2.0　littleCMS 2.18
RSWOP.icm                     class=prtr space=CMYK  218103 bytes  Agfa : Swop Standard
sRGB Color Space Profile.icm  class=mntr space=RGB     3144 bytes  sRGB IEC61966-2.1
```

可作轉換目標的 CMYK 輸出（prtr）描述檔：**1 個**。§9 指定的 Japan Color：**無**。

這一項直接決定產品形態。§10 Sprint 10 為了避開 Adobe ICC 的 EULA 轉嫁義務，OutputIntent
走 ICC registry 名稱（JC200103）免嵌描述檔；轉換繞不過這一關，因為轉換非得有描述檔的
實際位元組不可。故**不內建預設描述檔**，由使用者提供，且沿用既有的 ICC 選取器
（§10 Sprint 101）。

### 2.2 中性灰不守單 K

| intent | 256 階中 C／M／Y 非零 | 中灰 128 → CMYK | 純黑 0 → CMYK |
| --- | --- | --- | --- |
| 0 perceptual | 229 階 | (63, 53, 50, 92) | (0, 0, 0, 255) |
| 1 relative colorimetric | 254 階 | (63, 53, 50, 94) | (0, 0, 0, 255) |
| 2 saturation | 255 階 | (82, 95, 95, 255) TAC 207% | **(63, 73, 81, 255) TAC 185%** |
| 3 absolute colorimetric | 255 階 | (65, 54, 54, 79) | (0, 0, 0, 255) |

兩個結論：

1. **灰階來源永不進轉換路徑。**中灰經 ICC 轉出四色灰，違反 §9「灰階照片走單 K」，
   且把原本 TAC ≤ 100% 的單 K 影像推成四色相加。四色灰在印刷上還多一層套印風險
   （四版沒對準即偏色），這正是 §9 要求單 K 的理由。既有 `images.open_placed` 已把
   灰階類來源收成 `L`，本結論等於「維持不動」，不是新增機制。
2. **saturation intent 直接排除。**它連純黑都轉成四色（TAC 185%），對送印稿是破壞性的。
   absolute colorimetric 亦不開放（它保留來源白點，用於打樣模擬紙白，非成品輸出用途）。

### 2.3〜2.5 真素材：TAC、intent 差異、耗時

素材 740×925 RGB，來源無內嵌描述檔（依 sRGB 假設，依據見 §2.6）。

| intent | 最高 TAC | 平均 TAC | 往返 RGB 平均差 | 耗時 |
| --- | --- | --- | --- | --- |
| 0 perceptual | 291.4% | 121.1% | 28.88／255 | 39 ms |
| 1 relative colorimetric | **282.7%** | 122.4% | 26.87／255 | 28 ms |
| 2 saturation | 298.4% | 184.9% | 84.71／255 | 29 ms |
| 3 absolute colorimetric | 284.7% | 118.2% | 28.33／255 | 29 ms |

- **TAC 全數低於 §9 的 320% 門檻。**pre-mortem 列的 TAC 超標風險（估 40%）**未成真**，
  但成因是 SWOP 描述檔自身的墨量限制，換一個高墨量描述檔結論可能翻轉，故實作仍須
  把轉出影像餵給既有 `preflight.check_ink_coverage`，不可因為這次沒超標就省掉。
- **往返差不是誤差，是色域壓縮幅度。**26.87／255 的意思是這張高飽和藍有相當比例落在
  CMYK 色域外，轉換必然壓縮且不可逆。把它讀成「轉換不準」是誤讀。
- **intent 之間：平均差 5.45／255、最大差 199／255。**平均小是因為多數像素在色域內
  兩者一致；最大差大是因為色域外的處置方式根本不同（perceptual 整體壓縮、relative
  就近裁切）。本機沒有打樣，**無法判斷哪個對**，故 intent 必須是使用者可見可選的選項，
  預設取 relative colorimetric（印廠交件的通行預設，且本次量到的 TAC 最低）。
- 速度不構成限制：300ppi 滿版 1748×2480 為 106 ms。

### 2.6 來源描述檔的處置

內嵌 sRGB（作業系統的 `sRGB Color Space Profile.icm`，3144 bytes）與 `ImageCms` 合成的
sRGB，轉出 CMYK 的分量差為**平均 0.007／255、最大 1／255**（捨入級）。

故：帶內嵌描述檔者依其描述檔轉，未標記者假設 sRGB，兩條路在來源真為 sRGB 時等價，
不會因為「有沒有標記」而產生看得見的分歧。

### 2.7 反向（預覽 CMYK → sRGB）改用 ICC 的代價

| 樣本 | ICC 反算（無 BPC） | ICC 反算（帶 BPC） | 現行逐通道近似 |
| --- | --- | --- | --- |
| 內文暖黑 K92 | (52, 51, 51) 非中性 | (37, 36, 36) 非中性 | (20, 20, 20) |
| 實黑 K100 | (34, 33, 33) 非中性 | (2, 0, 0) 非中性 | (0, 0, 0) |
| 紙白 K0 | (255, 255, 255) | (255, 255, 255) | (255, 255, 255) |
| 富黑 60/40/40/100 | (30, 31, 26) 非中性 | (0, 0, 0) 中性 | (0, 0, 0) |

換過去的代價是：**每一頁內文都變淺並帶輕微色偏**（K92 由 20 變 52 或 37，且三分量不等）。
這在色彩管理上是「正確」的（印在紙上的單 K92 本來就不是純黑），但在編輯情境裡是退步：
編輯看的是稿，不是打樣。正確的形態是**軟打樣（soft proof）作為可切換的檢視模式**，
而不是把預覽的預設換掉，且軟打樣要成立還需要螢幕描述檔與標準觀察環境，兩者本專案都沒有。
故 (b) 維持現行逐通道近似，另立獨立項目。

## 3. 本 spike 驗不到的事

- **色彩正確性。**無打樣、無分光儀、無標準光源，本機不存在裁判。上列全部是機械性質。
- 只驗過**一個描述檔**（SWOP，美規塗布）與**一張素材**（高飽和藍的 3D 算圖）。膚色、
  中性照片、非塗布紙描述檔、Japan Color 皆未驗。
- 眼看複驗（`out/eyeball-對照.png`，Gate 1 親看）：perceptual 與 relative 都把那片藍
  推向青且看起來更飽和。**沒有負片、沒有通道錯位**（spike 18 那類失效未出現），但
  「看起來更飽和」是轉回 sRGB 顯示的結果，不代表印出來的樣子。
- 未驗轉換對 `/DCTDecode`（JPEG）來源的行為（既有 `open_placed` 對 CMYK JPEG 快速失敗，
  但本輪產出的是記憶體內 CMYK，不經該路徑）。

## 4. 限制與可重現性

- 重現：`python spikes/spike25-icc-cmyk/probe_icc_convert.py`。素材為 Sprint 137 R5 沿用的
  `out/sprint137-r5/cover-color.png`（Owner 機器上既有的 Windows Spotlight 桌布裁切，
  屬 3D 算圖非實拍照片），版權紅線：素材與產物皆留 `out/`，不入 repo。
- 探針的 TAC 複量走 PyMuPDF `xref_stream` 取解壓後原始樣本、於 Python 層逐四位元組相加，
  不經 PIL；PDF 結構層（色彩空間、有無 `/Decode`）亦由 PyMuPDF 讀，與寫出端獨立。
- 本報告不含任何「顏色會正確」的宣稱。實作若採納，該宣稱不得出現在 UI、CHANGELOG
  或說明文件中。
